# Нейроядро: руководство для разработчиков плагинов

**{{package}}**, версия **{{version}}** от {{versiondate}}

Это руководство — для тех, кто пишет свой плагин для SalesMan CRM и хочет
пользоваться нейросетью, не разбираясь с ключами, провайдерами, оплатой и
очередями. Всё это уже сделано в Нейроядре: подключаете его классы, регистрируете
свой промпт — и вызываете модель одной функцией.

Документ описывает только программный интерфейс ядра. Как настроить подключение,
ключ и цены — написано в справке самого плагина (файл `readme.md`, правая колонка
раздела «Нейроядро»).

Этот текст лежит в `plugins/neuroCore/developers.md` и открывается кнопкой
**Инструкция для разработчиков** в шапке раздела «Нейроядро». У каждого раздела
есть постоянная ссылка-якорь: на неё можно ссылаться в переписке или в задаче.

---

## Кому и зачем

Без ядра каждый нейро-плагин решает одни и те же задачи по-своему: хранит свой
ключ, сам ходит в HTTP, сам считает токены, сам придумывает, что делать с таймаутом.
Пользователь получает три разных места для ключа и три отчёта о расходе.

Нейроядро — общий слой под такими плагинами:

| Задача | Кто решает |
|---|---|
| Где лежит ключ, как он шифруется | ядро (`neuro_provider`, `Neuro\Crypto`) |
| Какой адрес API, модель, таймаут, цены | ядро (настройки подключения) |
| Как отправить запрос и разобрать ответ | ядро (`Neuro\Neuro`, `Neuro\Provider\*`) |
| Где живёт текст промпта и его версии | ядро (`neuro_prompt`, `neuro_prompt_rev`) |
| Что делать с долгими и массовыми вызовами | ядро (`neuro_task`, воркер по cron) |
| Сколько потрачено | ядро (`neuro_usage`) |
| Что не отправлять провайдеру | ядро (`Neuro\Pii`, настройка подключения) |
| **Что именно спросить и что делать с ответом** | **ваш плагин** |

Вторая половина последней строки — главное: ядро ничего не знает про вашу
предметную область. Сделку, письмо, звонок и результат его разбора хранит и
показывает ваш плагин.

## Требования

* SalesMan CRM 2025.2 и выше, PHP 7.2…8.1 — как у самого Нейроядра.
* Плагин `neuroCore` установлен и **включён**.
* В Нейроядре есть хотя бы одно **включённое подключение** к нейросети.
* Для работы очереди — плагин «Планировщик заданий» (`cronManager`).

Ваш плагин должен оставаться работоспособным, даже если ядра нет: включиться он
обязан в любом случае, иначе администратор не увидит ни плагина, ни причины
отказа. Это правило самого ядра, и оно же применимо к вам — см.
«[Деградация без ядра](#degradaciya-bez-yadra)».

## Как подключить ядро

Классы ядра лежат в `plugins/neuroCore/php/Class/` и грузятся автозагрузчиком
плагина. Подключите его один раз в начале файла:

```php
<?php

$rootpath = dirname(__DIR__, 3); // файл лежит в plugins/вашПлагин/php/

require_once $rootpath.'/inc/config.php';
require_once $rootpath.'/inc/dbconnector.php';
require_once $rootpath.'/inc/auth_main.php';
require_once $rootpath.'/inc/settings.php';
require_once $rootpath.'/inc/func.php';

// классы Нейроядра: namespace Neuro\* → plugins/neuroCore/php/Class/
require_once $rootpath.'/plugins/neuroCore/php/autoload.php';

use Neuro\Neuro;
use Neuro\Prompt;
use Neuro\Queue;
use Neuro\Security;
```

Дальше доступны все классы пространства имён `Neuro`: соответствие
`Neuro\Provider\Gemini` → `php/Class/Provider/Gemini.php`.

**Не правьте файлы ядра.** Обновление Нейроядра перезапишет вашу правку, и
сломается уже чужой плагин. Если возможностей не хватает — сначала посмотрите
раздел «[Частые ошибки](#chastye-oshibki)»: почти всё, чего, кажется, не хватает,
решается на стороне вашего плагина.

### Проверка готовности ядра {#proverka-gotovnosti}

Прежде чем показывать пользователю кнопку «Сгенерировать», проверьте три вещи:
ядро установлено, оно включено, в нём есть рабочее подключение.

```php
/**
 * Состояние ядра: установлено, включено, есть ли подключения.
 *
 * @param object $db
 * @param string $sqlname
 * @param int    $identity
 * @param string $rootpath
 *
 * @return array - installed, active, providers, error
 */
function my_core_status($db, string $sqlname, int $identity, string $rootpath): array {

	$out = [
		'installed' => file_exists($rootpath.'/plugins/neuroCore/php/autoload.php'),
		'active'    => false,
		'providers' => [],
		'error'     => '',
	];

	if (!$out['installed']) {
		return $out;
	}

	try {

		require_once $rootpath.'/plugins/neuroCore/php/autoload.php';

		$out['active'] = ((string)$db->getOne(
			"SELECT active FROM {$sqlname}plugins WHERE name = 'neuroCore' AND identity = ?i LIMIT 1",
			$identity
		) === 'on');

		if (!$out['active']) {
			return $out;
		}

		$out['providers'] = (array)$db->getAll(
			"SELECT id, name, model FROM {$sqlname}neuro_provider WHERE active = 'on' AND identity = ?i ORDER BY id",
			$identity
		);

	}
	catch (Throwable $e) {
		$out['error'] = $e->getMessage();
	}

	return $out;

}
```

Так же подключается и ядро в фоновом скрипте вашего плагина (свой cron-обработчик):
`require_once $rootpath.'/plugins/neuroCore/php/autoload.php';` — и всё.

### Деградация без ядра {#degradaciya-bez-yadra}

Ядро — отдельный плагин: его может не быть, он может быть выключен, а в нём может
не быть ни одного подключения. Во всех трёх случаях ваш плагин обязан:

* **включиться** — иначе администратор не увидит ни плагина, ни причины;
* **не падать** — ни на активации, ни на странице;
* **объяснить** — что именно сделать: «установите Нейроядро», «включите его»,
  «добавьте подключение в разделе Нейроядро».

Регистрацию промпта оборачивайте в `try/catch` и запоминайте результат в своих
настройках: тогда причина отказа видна на странице плагина, а не только в общем
`cash/actions.log`, который перезаписывают хуки других плагинов.

```php
try {

	$status = Neuro\Prompt::register($db, $sqlname, $code, $content, $params, 'myplugin', $identity, $iduser);

}
catch (Throwable $e) {

	// ядро есть, но регистрация не удалась: запоминаем причину для администратора
	$status = 'error: '.$e->getMessage();

}

$settings = (array)customSettings('myplugin');
$settings['CORE_PROMPT_STATUS'] = $status;

customSettings('myplugin', 'put', ['params' => $settings]);
```

Готовый пример проверки состояния ядра — в разделе
«[Проверка готовности ядра](#proverka-gotovnosti)».

## Первый вызов: быстрый старт

Три шага: зарегистрировать промпт при активации, вызвать его по коду, показать
человеку либо текст ответа, либо причину отказа.

```php
<?php

use Neuro\Neuro;
use Neuro\Prompt;

// 1. При активации плагина — один раз: промпт появляется в реестре ядра.
Prompt::register(
	$db,
	$sqlname,
	'myplugin.deal.summary',           // код промпта
	file_get_contents(__DIR__.'/resources/deal.prompt'), // текст с {{переменными}}
	['temperature' => 0.3, 'max_tokens' => 700],
	'myplugin',                        // owner — пакет вашего плагина
	(int)$identity,
	(int)$iduser1
);

// 2. В момент, когда нужен ответ модели.
$neuro = new Neuro($db, $sqlname, (int)$identity, $rootpath);

$res = $neuro->ask([
	'prompt' => 'myplugin.deal.summary',
	'tags'   => [
		'client' => 'ООО «Ромашка»',
		'amount' => '1 200 000 ₽',
		'stage'  => 'Согласование договора',
	],
	'iduser' => (int)$iduser1,   // кто инициировал: попадёт в расход и в журнал
]);

// 3. Ошибку показываем человеку — это единственный правильный вариант.
if ($res['error'] !== NULL) {

	print 'Не удалось получить ответ: '.$res['error']['message'];

}
else {

	print $res['text'];   // ответ модели

}
```

Ответ приходит всегда одной и той же структуры — и при успехе, и при любой
неудаче. Поэтому проверка `error` обязательна: `text` при ошибке пустой, и без
проверки пользователь увидит пустое окно вместо причины.

## Реестр промптов

### Код промпта

Код — это стабильный ключ: `myplugin.deal.summary`. Ядро приводит его к нижнему
регистру, так что `MyPlugin.Deal.Summary` и `myplugin.deal.summary` — один промпт.

Соглашение: `<пакет плагина>.<что делает>`. Код попадает в отчёты о расходе и в
журнал, поэтому по нему должно быть понятно, чей это вызов. **Не меняйте код после
релиза** — иначе расход разъедется на две строки, а сохранённый администратором
текст останется в старом промпте.

### Регистрация промпта

`Prompt::register()` вызывается при активации и при обновлении плагина:

```php
/**
 * @return string - created | exists | differs | skipped
 */
$status = Prompt::register($db, $sqlname, $code, $content, $params, $owner, $identity, $iduser);
```

| Что вернулось | Что это значит |
|---|---|
| `created` | промпта не было — создан (версия 1, `source = plugin`) |
| `exists` | промпт есть, текст совпадает с тем, что приносит плагин |
| `differs` | в реестре другой текст: администратор правил или плагин обновил свой вариант |
| `skipped` | пустой код или пустой текст — регистрировать нечего |

`differs` — это **не ошибка**. Текстом промпта владеет администратор: он может
поправить формулировку под свой бизнес, и обновление плагина не имеет права
затирать эту правку. Ядро запоминает ваш текст в `plugin_content`, показывает
расхождение в интерфейсе, а решение принимает человек.

Отдельно про регистрацию при **обновлении**: вызывайте `register()` и там. Так
новый текст промпта доедет до тех, кто ещё не правил его руками, а у остальных
появится пометка о расхождении.

### Где хранить текст по умолчанию

Держите текст промпта отдельным файлом рядом с ресурсами плагина
(`resources/deal.prompt`) — как это делает `neuroRop`. Причины простые: текст
промпта длинный, в PHP-файле он мешает читать код, а в файле его можно
посмотреть и поправить без правки кода.

```php
$promptText = file_get_contents($rootpath.'/plugins/myplugin/resources/deal.prompt');
```

### Переменные шаблона

Промпт — это Mustache-шаблон. Подставляются значения из `tags`:

```text
Ты — ассистент отдела продаж. Разбери сделку.

Клиент: {{client}}
Сумма: {{amount}}
Этап: {{stage}}

{{#history}}
- {{datum}}: {{comment}}
{{/history}}
```

Правила, которые важно знать:

* Экранирования HTML нет намеренно: в промпт идут реальные данные CRM, и
  `&quot;` вместо кавычки испортил бы запрос. Ваши данные уходят провайдеру как есть.
* Доступны секции `{{#список}}…{{/список}}` и вложенные пути `{{client.name}}`.
* **Отсутствующая переменная — это ошибка, а не пустое место.** Если в `tags` нет
  ключа, использованного в промпте, вызов не уходит провайдеру: ответ придёт с
  ошибкой `prompt_tags` и списком недостающих переменных. Это защита от запроса с
  дырами, на который модель ответит непредсказуемо.

> **Осторожно с секциями.** Проверка переменных ищет в тексте только простые
> `{{имя}}` — она не знает ни секций, ни контекста. В примере выше `{{datum}}` и
> `{{comment}}` лежат внутри `{{#history}}`, и если положить в `tags` только
> `'history' => [...]`, проверка сочтёт их отсутствующими и вызов не состоится.
> Поэтому имена переменных из секции нужно дублировать на верхнем уровне `tags`
> (хотя бы пустыми значениями) — или не использовать секции там, где вызов идёт
> через `ask()` и очередь.

```php
$missing = \Neuro\Prompt::missing($promptText, $tags);

if (!empty($missing)) {
	// «В промпте не хватает переменных: client, amount»
}
```

Проверять заранее стоит там, где ошибку уже не увидит человек — при постановке
задания в очередь (в фоне рендер промпта никто не покажет).

### Параметры промпта

Параметры — это JSON в реестре, они дополняют подключение:

| Ключ | Что задаёт |
|---|---|
| `provider_id` | конкретное подключение (иначе — первое включённое) |
| `model` | модель вместо указанной в подключении |
| `temperature` | «температура» ответа |
| `max_tokens` | ограничение длины ответа |
| `timeout` | таймаут запроса, секунд (5…300) |
| `system` | системная роль: отдельное сообщение `system` перед промптом |
| `json_schema` | схема ответа, см. «[JSON-ответы](#json-otvety)» |

Разовая замена работает для `model`, `temperature`, `max_tokens`, `timeout` и
`json_schema` — их можно передать тем же ключом в `ask()`. Два исключения: `system`
задаётся только параметрами промпта (в `ask()` он не читается), а `provider_id`
работает и там, и там — в задании очереди он берётся из самого задания.

## Фасад `Neuro\Neuro`

### Создание

```php
$neuro = new Neuro($db, $sqlname, (int)$identity, $rootpath);
```

Все четыре аргумента необязательны: без них берутся глобальные `$db`, `$sqlname`,
`$identity`, `$rootpath`. Но в своём коде лучше указать их явно — так функция
остаётся рабочей и в фоне, и в тесте, где глобальных переменных нет.

### `ask()` — вызов промпта из реестра

| Параметр | Обяз. | Что это |
|---|---|---|
| `prompt` | да | код промпта из реестра |
| `tags` | — | переменные шаблона |
| `iduser` | — | кто инициировал: расход, журнал, уведомления |
| `provider_id` | — | вызвать конкретное подключение |
| `model`, `temperature`, `max_tokens`, `timeout` | — | разовое переопределение |
| `json_schema` | — | схема ответа вместо заданной в промпте |

### Контракт ответа

Возвращается всегда один и тот же массив:

| Ключ | Тип | Что содержит |
|---|---|---|
| `text` | string | ответ модели как текст |
| `json` | array\|null | разобранный JSON, если была схема и она сошлась |
| `usage` | array | `in`, `out` — токены; `cost` — стоимость или `null` |
| `model` | string | модель, которая фактически ответила |
| `latency_ms` | int | сколько занял вызов (у кэша — `0`) |
| `error` | array\|null | `code` и `message`; `null` — вызов удался |
| `schema_errors` | array | чего не хватило ответу до схемы |
| `retried` | bool | `true` — в результат попал повтор после несоответствия схеме |
| `prompt` | string | код промпта |
| `prompt_version` | int | версия промпта, с которой работали |
| `provider` | string | название подключения |
| `cached` | bool | `true` — ответ взят из кэша, вызова не было |

### Ошибки

`error.code` — машиночитаемая причина, `error.message` — текст для человека,
который можно показывать как есть.

| Код | Что случилось | Что делать плагину |
|---|---|---|
| `prompt_code` | не передан код промпта | ошибка в вашем коде |
| `prompt_missing` | промпт не найден или выключен | сказать администратору: включить промпт в Нейроядре |
| `prompt_tags` | в промпте нет переменных из `tags` | дополнить `tags`; список — в тексте сообщения |
| `provider_missing` | нет ни одного включённого подключения | сказать администратору: добавить подключение |
| `provider_key` | ключ не задан, не читается или не расшифровывается | причина уже ушла администратору оповещением |
| `http_401`, `http_403` | ключ отклонён или отозван | показать причину; повтор не поможет |
| `http_429` | превышен лимит запросов | повторить позже (в очереди ядро сделает это само) |
| `http_5xx`, `timeout`, `network` | сбой на стороне провайдера или сети | повторить позже; ядро повторит в очереди |
| `http_400`, `http_4xx` | ошибка в запросе (модель, формат) | показать причину: обычно это параметры промпта |
| `api_error` | провайдер вернул ошибку внутри ответа 200 | показать `message` |
| `parse` | ответ не удалось разобрать | проверить схему и промпт |
| `empty` | провайдер вернул пустой ответ | показать причину; автоматического повтора нет — только `Queue::retry()` вручную |
| `safety` | ответ заблокирован правилами провайдера | показать человеку, повторить бессмысленно |
| `worker` | сбой воркера при выполнении задания | смотреть журнал Нейроядра |

Правило: **`error` проверяется всегда**. Единственное исключение — когда вы
намеренно игнорируете неудачу (например, генерируете черновик и любой ответ
лучше пустоты); и тогда это должно быть написано в комментарии.

### `request()` — вызов без промпта из реестра

Нужен, когда запрос собирается вами (своя переписка из нескольких сообщений или
свой диагностический запрос). Промпт в реестре при этом не используется:

```php
$res = $neuro->request([
	'messages' => [
		['role' => 'system', 'content' => 'Отвечай кратко.'],
		['role' => 'user', 'content' => 'Сколько будет 2+2?'],
	],
	'temperature' => 0,
	'max_tokens'  => 100,
	'code'        => 'myplugin.chat',   // только для отчёта о расходе
]);
```

Учёт расхода здесь общий: вызов, вернувший токены, попадёт в отчёт под указанным
`code`. А вот контракт ответа **другой** — это ответ адаптера, а не результат
`ask()`: есть `text`, `json`, `usage`, `model`, `latency_ms`, `error` и служебный
`raw` (тело ответа провайдера), но нет `schema_errors`, `retried`, `prompt`,
`prompt_version`, `provider`, `cached`. Кэш, версии промпта, проверка по схеме и
повтор при несоответствии к такому вызову не применяются — это ваш запрос целиком.
Читайте только перечисленные поля и не полагайтесь на остальные.

## JSON-ответы {#json-otvety}

Модели редко отдают чистый JSON: обычно это блок ```json … ``` или текст с
пояснением. Ядро извлекает JSON терпимо (целиком, из блока, первый сбалансированный
объект), а проверяет строго. Вам остаётся прочитать `json`.

### Формат схемы

```php
$res = $neuro->ask([
	'prompt'      => 'myplugin.deal.summary',
	'tags'        => $tags,
	'json_schema' => [
		'name'   => 'deal_summary',
		'schema' => [
			'type'       => 'object',
			'properties' => [
				'summary'      => ['type' => 'string'],
				'risk'         => ['type' => 'string', 'enum' => ['низкий', 'средний', 'высокий']],
				'next_actions' => ['type' => 'array', 'items' => ['type' => 'string']],
			],
			'required'   => ['summary', 'risk', 'next_actions'],
		],
	],
]);

if ($res['error'] === NULL && $res['json'] !== NULL) {
	$risk = $res['json']['risk'];
}
```

`name` и `schema` — тот же формат, что у OpenAI. Можно передать и «голую» схему
без обёртки — ядро поймёт оба варианта.

### Что поддерживается из JSON Schema

`type` (строка или список), `properties`, `required`, `items`, `enum`, `const`.
Этого достаточно для задач CRM. Более сложные конструкции (например,
`anyOf`/`$ref`) молча не проверяются — не рассчитывайте на них.

### Повтор при несоответствии

Если ответ не сошёлся со схемой, ядро один раз переспрашивает модель, добавляя в
переписку причину. В расход попадают оба вызова. `retried = true` означает, что
в результат попал именно повтор (он сошёлся со схемой или упал с ошибкой); если
оба ответа мимо схемы, возвращается первый, а причины остаются в `schema_errors`.

### Режим JSON в подключении

У подключения есть настройка `json_mode` (`off` / `json_object` / `json_schema`).
По умолчанию `off`, и это правильно: не все OpenAI-совместимые API принимают
`response_format` и роняют вызов целиком. Схему обеспечивают текст промпта, разбор
ответа и повтор. Если провайдер умеет — администратор включает режим в подключении.

## Очередь заданий

### Когда очередь нужна, а когда нет

| Ситуация | Как вызывать |
|---|---|
| Пользователь нажал кнопку и ждёт ответа (резюме сделки, черновик письма) | `ask()` напрямую — ответ за секунды, человек видит результат сразу |
| Массовая операция: 300 клиентов, разбор истории, рассылка | очередь: `Queue::push()` |
| Ответ нужен не сейчас, а «когда будет» | очередь + уведомление (`payload.notify`) |

Очередь существует потому, что массовая операция в запросе страницы — это
таймаут, потеря результата и оплаченный, но не полученный ответ. Задание в
очереди переживает перезапуск сервера и при временном сбое повторяется с растущей
паузой.

### Постановка задания

```php
use Neuro\Queue;

$id = Queue::push($db, $sqlname, [
	'code'           => 'myplugin.deal.summary', // = код промпта
	'prompt_id'      => (int)$prompt['id'],
	'prompt_version' => (int)$prompt['version'],
	'provider_id'    => 0,                       // 0 — первое включённое подключение
	'priority'       => 5,                       // 1..9, меньше — важнее
	'ref'            => 'deal',                  // тип сущности CRM
	'refid'          => (int)$dealId,            // её id
	'payload'        => [
		'tags'   => ['client' => 'ООО «Ромашка»', 'amount' => '1 200 000 ₽'],
		'req'    => ['temperature' => 0.3, 'timeout' => 60],
		'notify' => true,
	],
	'iduser'         => (int)$iduser1,
	'max_attempts'   => 3,
], (int)$identity);
```

| Поле задания | Смысл |
|---|---|
| `code` | код промпта; воркер вызовет именно его |
| `prompt_id`, `prompt_version` | для интерфейса и отпечатка; версия не фиксируется (см. ниже) |
| `provider_id` | подключение; `0` — взять первое включённое |
| `priority` | порядок разбора, меньше — раньше |
| `ref`, `refid` | к чему относится задание: по ним вы найдёте результат |
| `payload.tags` | переменные промпта |
| `payload.req` | разовые переопределения (`model`, `temperature`, `max_tokens`, `timeout`, `json_schema`) |
| `payload.notify` | `true` — уведомить автора об успехе (об окончательной ошибке ядро уведомляет всегда) |
| `iduser` | автор задания |
| `max_attempts` | сколько всего попыток при временных сбоях |

`ref` — это ваш ярлык типа сущности, а не имя таблицы: сделку CRM называет `deal`
(хотя лежит она в `dogovor`), клиента — `client`. Единственное требование — чтобы
этот же ярлык понимал ваш код, который потом ищет результат.

`Queue::push()` возвращает id задания; `0` — задание не создано (пустой код).
Ошибку базы функция не глотает, а бросает исключение: вызывайте её в `try/catch`,
как в примере с массовой операцией ниже.

**Версия промпта не фиксируется.** Если администратор поправил промпт, пока
задание ждало очереди, применится исправленный текст. Так задумано: отправлять
модели заведомо устаревшую инструкцию хуже, чем применить свежую.

**Провайдер берётся из задания.** Если в задании `provider_id = 0`, будет
использовано первое включённое подключение — `provider_id` из параметров промпта
для заданий очереди не применяется.

### Идемпотентность

Отпечаток задания — `sha256(code|prompt_version|payload|iduser)`. Если такое
задание уже стоит в очереди или выполняется, второе не создаётся: `push()` вернёт
id первого. Двойной клик по кнопке не оплачивается дважды.

Два следствия, о которых легко забыть:

* `ref` и `refid` **не входят** в отпечаток. Если вы ставите однотипные задания
  разным клиентам, различающиеся данные обязаны быть в `payload.tags` — иначе
  второе задание будет считаться дублем первого. `ref`/`refid` для этого не годятся.
* отпечаток считается по версии промпта, а выполняется задание по актуальной
  версии. Правка промпта между двумя постановками даст разные отпечатки — это нормально.

### Как забрать результат

Ядро выполняет задание и записывает ответ в `{sqlname}neuro_task`. **Свой код ядро
не вызывает**: колбэков «задание выполнено» нет. Результат забирает ваш плагин —
по `ref`/`refid`, которые вы указали при постановке.

Результат живёт в полях задания:

| Поле | Что там |
|---|---|
| `status` | `new`, `run`, `ok`, `error`, `cancel` |
| `result` | текст ответа модели |
| `result_json` | разобранный JSON (если была схема) |
| `error`, `error_code` | причина отказа |
| `tokens_in`, `tokens_out`, `cost`, `model`, `latency_ms` | расход по заданию |
| `attempts`, `max_attempts` | попытки |

Забирать удобно в двух местах: при открытии карточки сущности (чтобы показать
готовое) и в собственном cron-обработчике (чтобы разложить результаты пачкой).
Пример функции — в разделе «[Сбор результатов](#sbor-rezultatov)».

Выборка по своим заданиям выглядит так (префикс таблиц — ваш `$sqlname`):

```sql
SELECT id, ref, refid, status, result, result_json, error, error_code, tokens_in, tokens_out
  FROM app_neuro_task
 WHERE identity = 1
   AND code = 'neuroexample.deal.summary'
   AND ref = 'deal'
   AND status IN ('ok', 'error')
 ORDER BY id DESC
 LIMIT 50
```

Фильтр по `ref`/`refid` попадает в индекс `ref` (`ref`, `refid`) — по нему выборка
своих заданий не сканирует таблицу целиком.

**Срок хранения.** Выполненные задания старше срока хранения (по умолчанию 30
дней) удаляет воркер. Незавершённые не удаляются никогда, отменённые — тоже. Если
результат нужен вам надолго — перенесите его в свою таблицу (что и делает пример
ниже).

**Переменные задания.** После успешного выполнения `payload` очищается: в нём
лежали данные клиентов. У заданий с ошибкой переменные остаются — иначе причину
не разобрать. Если администратор включил настройку «Сохранять переменные задания
после выполнения», они останутся у всех заданий.

### Статусы, повтор и отмена

* Временные сбои (`http_429`, `http_5xx`, `timeout`, `network`) повторяются
  автоматически с паузой 60, 120, 240 секунд… но не больше часа, и не дольше
  `max_attempts` попыток.
* Отказ по ключу, политике контента или неверному запросу не повторяется: это
  только тратило бы деньги владельца.
* Задание в работе отменить нельзя — запрос уже отправлен и будет оплачен.
  `Queue::cancel()` отменяет только то, что ещё не начато.
* `Queue::retry()` возвращает в очередь задание со статусом `error`/`cancel`.
* Задание, взятое воркером и брошенное (сервер упал, процесс убит), через 15
  минут возвращается в очередь: `Queue::reclaim()`.

### Планировщик

Очередь разбирает воркер ядра — `plugins/neuroCore/cron/worker.php`, задание
создаётся при активации и обновлении Нейроядра. **Своего задания для этого
заводить не нужно**, и не нужно вызывать воркер из своего кода.

Проверять вручную (на сервере, из консоли):

```bash
php plugins/neuroCore/cron/worker.php --limit=5 --verbose
```

Если планировщик не установлен или не запускается, задания будут копиться, а
Нейроядро сообщит об этом администраторам. Плагину-фиче в этом случае достаточно
показать пользователю честный статус: «задание в очереди» — а не «ошибка».

## Расход и оценка стоимости

Расход учитывает само ядро: каждый вызов, вернувший токены, попадает в
`neuro_usage` под кодом промпта. Вам ничего делать не нужно — кроме одного:
**не вызывайте адаптеры провайдеров напрямую** (`Neuro\Providers::make(...)` →
`chat()`), иначе вызов уйдёт мимо отчёта, и владелец увидит траты без объяснения.

Стоимость считается только по ценам, заданным в подключении. Если цен нет, в
отчёте будут точные токены, а сумма — пустой: ядро не выдумывает прайс.

Перед массовой операцией стоит показать оценку — «будет 300 вызовов, это примерно
X». История вызовов для этого уже есть:

```php
use Neuro\Providers;
use Neuro\Usage;

$average = Usage::average($db, $sqlname, (int)$identity, 'myplugin.deal.summary');

$provider = Providers::byId($db, $sqlname, (int)$providerId, (int)$identity);

$estimate = Usage::estimate(count($deals), $average, Providers::prices($provider));

if ($estimate['priced']) {
	print 'Примерно '.$estimate['cost'].' '.$estimate['currency'].' за '.$estimate['calls'].' вызовов';
}
else {
	print 'Оценка невозможна: '.$estimate['reason']; // например, не заданы цены
}
```

Оценка честно помечает себя как невозможную (`priced = false`), если истории
вызовов или цен нет. Показывать вместо неё ноль нельзя: ноль читается как
«бесплатно».

## Кэш ответов

Кэш ядра сравнивает отпечаток запроса: код и версию промпта, тип подключения и сам
запрос — то есть подставленные в шаблон данные, модель, температуру, лимит токенов
и схему ответа. Таймаут в отпечаток не входит. Отпечаток совпал — модель не
вызывается, ответ берётся из сохранённого.

* В ответе это видно по `cached = true` и `latency_ms = 0`. Интерфейс должен
  написать «взято из кэша» и не показывать новую задержку.
* Такой ответ **не попадает в расход**: вызова не было.
* Срок жизни кэша задаётся в настройках ядра (по умолчанию 60 минут, `0` —
  выключить). Плагин на это не влияет.
* В кэш кладётся только удачный ответ: ошибку кэшировать нельзя, иначе временный
  сбой провайдера повторялся бы из кэша весь срок жизни.
* Отпечаток считается **до** маскирования персональных данных: иначе у разных
  клиентов маскированный текст совпал бы, и один клиент получил бы ответ,
  подготовленный для другого.

Что это значит для вас: одинаковый запрос по одинаковым данным может вернуться
мгновенно и не «свежим» вызовом. Если ответ обязан быть новым (например,
пользователь нажал «Обновить») — меняйте данные в `tags`, а не надейтесь на
настройку ядра.

## Персональные данные клиента

В подключении есть переключатель «Разрешить отправлять персональные данные
клиентов» (`pd_allowed`). Если он снят, ядро само заменяет телефоны, почту, ФИО и
реквизиты условными обозначениями `[PHONE_1]`, отправляет запрос и **подставляет
настоящие значения обратно** в ответе. Ваш код видит обычный результат и ничего
делать не должен.

Что стоит знать:

* факт маскирования отмечается в журнале ядра — без самих значений;
* названия компаний, должности и текст переписки не маскируются: это защита от
  утечки реквизитов, а не полная анонимизация;
* если промпт требует точных данных (например, «проверь, верно ли написан
  телефон»), при включённом маскировании ответ будет бессмысленным — предупредите
  об этом в справке плагина.

## Журнал

Журнал ядра отвечает на вопрос «что происходило»: итоги заданий, отказы
подключений, уборка кэша, маскирование. Свои события пишите туда же — тогда
администратору не придётся смотреть в два места:

```php
use Neuro\Log;

Log::write($db, $sqlname, 0, 'info', 'Плагин «Мой»: запущена массовая генерация', [
	'deals'  => count($deals),
	'iduser' => (int)$iduser1,
], (int)$identity);
```

Уровни: `debug`, `info`, `warn`, `error`. **Не пишите в журнал тексты промптов и
ответы модели** — для этого есть карточка задания. И никогда не пишите туда
значения ключей и персональные данные.

Задания из очереди журналируются ядром автоматически; `Queue::log()` — тот же
журнал, оставлен для совместимости.

## Оповещения администратора: хук `neurocore.alert`

Если подключение перестало работать или очередь встала, ядро оповещает
администраторов само: «колокольчик» CRM, запись в журнал и хук для внешних
каналов. Подпишитесь на хук, если у вас есть мост в Telegram/Viber:

```php
global $hooks;

$hooks->add_action('neurocore.alert', 'myplugin_neurocore_alert');

/**
 * Оповещение Нейроядра: одно событие в массиве.
 *
 * @param array $alerts - [['key' => 'queue' | 'key:DeepSeek', 'title' => ..., 'text' => ..., 'context' => [...]]]
 */
function myplugin_neurocore_alert(array $alerts): void {

	foreach ($alerts as $alert) {

		// key   — что именно случилось: 'queue' (очередь встала) или 'key:Подключение'
		// title — «Нейроядро: очередь не разбирается»
		// text  — подробности, значение ключа в текст не попадает
		myplugin_send_to_telegram((string)$alert['title'].': '.(string)$alert['text']);

	}

}
```

Исключение из обработчика ядро погасит — вызов обёрнут в `try/catch`, — но
остальные подписчики этого хука при этом не выполнятся: `do_action` прервётся на
первом же сбое. Поэтому обработчик не должен ни бросать исключения, ни тормозить.
Одно и то же оповещение не повторяется чаще, чем задано в настройках ядра (по
умолчанию раз в 6 часов).

## Уведомления пользователю

Для своих сообщений используйте тот же механизм, что и ядро:

```php
use Neuro\Notify;

Notify::send((int)$iduser1, 'Мой плагин: готово', 'Обработано сделок: 12 из 12.');
```

Если задание ставилось с `payload.notify = true`, ядро уведомит автора и об успехе.
Об окончательной ошибке оно уведомляет **всегда**, независимо от флага: молча
упавшее задание — это потраченные деньги без результата. Флаг гейтит только
успех — иначе очередь засыпала бы пользователя сообщениями.

## Свои AJAX-эндпоинты: права и CSRF

Свой эндпоинт (обычно `php/modal.php` плагина) подключается так же, как страница,
и обязан:

1. проверить права — **до** обработки действий;
2. требовать CSRF-токен для всего, что меняет данные или тратит деньги;
3. брать `identity` и `iduser1` только из сессии.

```php
<?php

use Neuro\Security;

$rootpath = dirname(__DIR__, 3);

require_once $rootpath.'/inc/config.php';
require_once $rootpath.'/inc/dbconnector.php';
require_once $rootpath.'/inc/auth_main.php';
require_once $rootpath.'/inc/settings.php';
require_once $rootpath.'/inc/func.php';
require_once $rootpath.'/plugins/neuroCore/php/autoload.php';

$action = isset($_REQUEST['action']) ? (string)$_REQUEST['action'] : '';

/**
 * Ответ JSON и выход.
 */
function answer(array $data): void {

	header('Content-Type: application/json; charset=utf-8');

	print json_encode($data, JSON_UNESCAPED_UNICODE);

	exit();

}

// 1. Права: только администратор (или своя ролевая проверка).
if (!Security::isAdmin($db, $sqlname, (int)$iduser1, (int)$identity, $isadmin, $tipuser)) {

	http_response_code(403);

	answer(['status' => 'error', 'message' => 'Доступ запрещен']);

}

// 2. CSRF: изменяющие действия и всё, что тратит деньги.
//    Список — свой: здесь перечислены действия этого плагина.
$protected = ['summary.run', 'summary.queue'];

if (in_array($action, $protected, true)) {
	Security::requireToken(isset($_REQUEST['token']) ? $_REQUEST['token'] : '');
}

// 3. identity/iduser1 — из сессии, а не из запроса.
```

Токен для разметки страницы:

```php
$token = Neuro\Security::csrfToken(isset($_COOKIE['ses']) ? (string)$_COOKIE['ses'] : '', (int)$iduser1);
```

```html
<input type="hidden" name="token" value="<?php echo $token ?>">
```

`Security::requireToken()` при несовпадении отдаёт JSON с понятной причиной
(«обновите страницу и повторите действие») и завершает запрос: тихо продолжать
нельзя — действие тратит деньги пользователя.

## Таблицы ядра

Префикс таблиц берётся из `$sqlname` (`Schema::tableName()`):

| Таблица | Что внутри | Кто пишет |
|---|---|---|
| `{sqlname}neuro_provider` | подключения: адрес, модель, ключ (имя переменной окружения или зашифрованное значение), цены | администратор через интерфейс |
| `{sqlname}neuro_prompt` | реестр промптов: текст, параметры, владелец, версия | `Prompt::register()` и администратор |
| `{sqlname}neuro_prompt_rev` | версии промптов | `Prompt::save()` |
| `{sqlname}neuro_task` | очередь заданий и результаты | `Queue::*` и воркер |
| `{sqlname}neuro_usage` | расход по дням, сотрудникам, кодам, моделям | `Usage::record()` из фасада |
| `{sqlname}neuro_cache` | кэш ответов | `Neuro::run()` |
| `{sqlname}neuro_log` | журнал | `Log::write()` и ядро |

Правило простое: **в таблицы ядра пишет только ядро**. Единственное исключение —
`Queue::push()`. Прямой `INSERT`/`UPDATE` по `neuro_*` из вашего плагина сломает
и отпечатки заданий, и отчёт о расходе, и уборку по сроку.

Свои данные (кто, когда, что получил) держите в своей таблице — как в примере ниже.

### Работа с ядром: `php/core.php`

```php
<?php
/* plugins/neuroExample/php/core.php */

/**
 * Код промпта. Менять после релиза нельзя: по нему считается расход.
 */
define('NEX_PROMPT_CODE', 'neuroexample.deal.summary');

/**
 * Текст промпта: сначала правка администратора, потом — файл плагина.
 */
function nex_prompt_text(string $rootpath): string {

	$file = $rootpath.'/plugins/neuroExample/resources/deal.prompt';

	return file_exists($file) ? (string)file_get_contents($file) : '';

}

/**
 * Параметры промпта: модель из подключения, ответ — короткий текст.
 */
function nex_prompt_params(): array {

	return [
		'temperature' => 0.3,
		'max_tokens'  => 700,
	];

}

/**
 * Загрузка ядра. Возвращает false, если Нейроядра нет.
 */
function nex_core_load(string $rootpath): bool {

	if (!file_exists($rootpath.'/plugins/neuroCore/php/autoload.php')) {
		return false;
	}

	require_once $rootpath.'/plugins/neuroCore/php/autoload.php';

	return class_exists('Neuro\\Neuro');

}

/**
 * Регистрация промпта в реестре ядра.
 *
 * @return string - created | exists | differs | skipped | unavailable | error: ...
 */
function nex_register_prompt($db, string $sqlname, int $identity, int $iduser = 0): string {

	$rootpath = $GLOBALS['rootpath'];

	if (!nex_core_load($rootpath)) {
		return 'unavailable';
	}

	try {

		return Neuro\Prompt::register(
			$db,
			$sqlname,
			NEX_PROMPT_CODE,
			nex_prompt_text($rootpath),
			nex_prompt_params(),
			'neuroExample',
			$identity,
			$iduser
		);

	}
	catch (Throwable $e) {

		return 'error: '.$e->getMessage();

	}

}
```

### Одиночный вызов: `php/modal.php`

```php
<?php
/* plugins/neuroExample/php/modal.php */

use Neuro\Neuro;
use Neuro\Prompt;
use Neuro\Queue;
use Neuro\Security;

$rootpath = dirname(__DIR__, 3);

require_once $rootpath.'/inc/config.php';
require_once $rootpath.'/inc/dbconnector.php';
require_once $rootpath.'/inc/auth_main.php';
require_once $rootpath.'/inc/settings.php';
require_once $rootpath.'/inc/func.php';
require_once __DIR__.'/core.php';

$action = isset($_REQUEST['action']) ? (string)$_REQUEST['action'] : '';

function answer(array $data): void {

	header('Content-Type: application/json; charset=utf-8');

	print json_encode($data, JSON_UNESCAPED_UNICODE);

	exit();

}

// ядро обязательно: без него ни промпта, ни вызова
if (!nex_core_load($rootpath) || !class_exists('Neuro\\Neuro')) {
	answer(['status' => 'error', 'message' => 'Не установлено Нейроядро: обратитесь к администратору']);
}

// мутации и всё, что тратит деньги, — только с токеном
if (in_array($action, ['summary.run', 'summary.queue'], true)) {
	Security::requireToken(isset($_REQUEST['token']) ? $_REQUEST['token'] : '');
}

switch ($action) {

	case 'summary.run':

		$dealId = (int)(isset($_REQUEST['refid']) ? $_REQUEST['refid'] : 0);

		// Сделки в этой CRM лежат в таблице dogovor: did — номер, kol — сумма,
		// sid — этап. Значения подставляются в {{client}}, {{amount}} и так далее.
		$deal = $db->getRow("SELECT did, title, kol, sid, iduser FROM {$sqlname}dogovor WHERE did = ?i AND identity = ?i", $dealId, (int)$identity);

		if (empty($deal)) {
			answer(['status' => 'error', 'message' => 'Сделка не найдена']);
		}

		$tags = [
			'client'  => (string)$deal['title'],
			'amount'  => (string)$deal['kol'],
			'stage'   => (string)$deal['sid'],
			'manager' => (string)$deal['iduser'],
		];

		$prompt = Prompt::byCode($db, $sqlname, NEX_PROMPT_CODE, (int)$identity);

		if (empty($prompt)) {
			answer(['status' => 'error', 'message' => 'Промпт «'.NEX_PROMPT_CODE.'» не найден: включите его в Нейроядре']);
		}

		$missing = Prompt::missing((string)$prompt['content'], $tags);

		if (!empty($missing)) {
			answer(['status' => 'error', 'message' => 'Не хватает данных для промпта: '.implode(', ', $missing)]);
		}

		$neuro = new Neuro($db, $sqlname, (int)$identity, $rootpath);

		$res = $neuro->ask([
			'prompt' => NEX_PROMPT_CODE,
			'tags'   => $tags,
			'iduser' => (int)$iduser1,
		]);

		if ($res['error'] !== NULL) {
			answer(['status' => 'error', 'message' => $res['error']['message'], 'code' => $res['error']['code']]);
		}

		answer([
			'status'  => 'ok',
			'text'    => (string)$res['text'],
			'cached'  => (bool)$res['cached'],
			'model'   => (string)$res['model'],
			'tokens'  => (int)$res['usage']['in'].'/'.(int)$res['usage']['out'],
		]);

		break;

	case 'summary.queue':

		$dealIds = array_map('intval', (array)(isset($_REQUEST['deals']) ? $_REQUEST['deals'] : []));

		$prompt = Prompt::byCode($db, $sqlname, NEX_PROMPT_CODE, (int)$identity);

		if (empty($prompt)) {
			answer(['status' => 'error', 'message' => 'Промпт «'.NEX_PROMPT_CODE.'» не найден']);
		}

		$queued = 0;

		foreach ($dealIds as $dealId) {

			$deal = $db->getRow("SELECT did, title, kol, sid, iduser FROM {$sqlname}dogovor WHERE did = ?i AND identity = ?i", $dealId, (int)$identity);

			if (empty($deal)) {
				continue;
			}

			$tags = [
				'client'  => (string)$deal['title'],
				'amount'  => (string)$deal['kol'],
				'stage'   => (string)$deal['sid'],
				'manager' => (string)$deal['iduser'],
			];

			// в фоне ошибку рендера никто не увидит — проверяем переменные здесь
			if (!empty(Prompt::missing((string)$prompt['content'], $tags))) {
				continue;
			}

			try {

				$id = Queue::push($db, $sqlname, [
					'code'           => NEX_PROMPT_CODE,
					'prompt_id'      => (int)$prompt['id'],
					'prompt_version' => (int)$prompt['version'],
					'ref'            => 'deal',
					'refid'          => $dealId,
					'payload'        => [
						'tags'   => $tags,
						'notify' => false,
					],
					'iduser'         => (int)$iduser1,
					'max_attempts'   => 3,
				], (int)$identity);

			}
			catch (Exception $e) {

				// одна неудачная постановка не должна обрывать остальные
				continue;

			}

			if ($id > 0) {
				$queued++;
			}
		}

		answer(['status' => 'ok', 'message' => 'Заданий поставлено: '.$queued]);

		break;

}
```

### Сбор результатов {#sbor-rezultatov}

Задание выполнил воркер — результат лежит в `neuro_task`, а ваш плагин переносит
его к себе. Вызывайте эту функцию при открытии карточки (чтобы показать готовое
резюме) или из своего cron-обработчика:

```php
/**
 * Переносит готовые ответы ядра в таблицу плагина.
 *
 * @param object $db
 * @param string $sqlname
 * @param int    $identity
 * @param string $ref    - тип сущности ('deal')
 * @param int    $refid  - id сущности (0 — по всем)
 *
 * @return int - сколько результатов перенесено
 */
function nex_collect_results($db, string $sqlname, int $identity, string $ref = 'deal', int $refid = 0): int {

	$sql = "SELECT id, ref, refid, status, result, error, error_code
	          FROM {$sqlname}neuro_task
	         WHERE identity = ?i AND code = ?s AND ref = ?s AND status IN ('ok','error')";

	$args = [$identity, NEX_PROMPT_CODE, $ref];

	if ($refid > 0) {
		$sql .= " AND refid = ?i";
		$args[] = $refid;
	}

	$moved = 0;

	foreach ((array)$db->getAll($sql, ...$args) as $task) {

		// уже перенесено? (UNIQUE KEY task гарантирует, что дубля не будет)
		$exists = (int)$db->getOne(
			"SELECT COUNT(*) FROM {$sqlname}neuroexample WHERE task_id = ?i AND identity = ?i",
			(int)$task['id'],
			$identity
		);

		if ($exists > 0) {
			continue;
		}

		// задание с ошибкой тоже переносим: пользователю нужна причина, а не тишина
		$text = $task['status'] === 'ok'
			? (string)$task['result']
			: 'Ошибка: '.(string)$task['error'];

		$db->query("INSERT INTO {$sqlname}neuroexample SET ?u", [
			'task_id'  => (int)$task['id'],
			'ref'      => (string)$task['ref'],
			'refid'    => (int)$task['refid'],
			'result'   => $text,
			'identity' => $identity,
		]);

		$moved++;

	}

	return $moved;

}
```

Задание при этом из ядра не удаляется: его уберёт уборка по сроку. Если результат
нужен надолго — он уже у вас в таблице.

Вызывать её удобно на странице раздела или в карточке — перед выводом резюме:

```php
// например, в index.php плагина при открытии карточки сделки
nex_collect_results($db, $sqlname, (int)$identity, 'deal', (int)$dealId);
```

Фоновый вариант — свой cron-обработчик плагина, который раз в несколько минут
переносит результаты по всем сущностям сразу (тогда `refid` не передаётся).

## Чек-лист интеграции

Перед релизом пройдитесь по списку:

- [ ] Классы ядра подключаются через `plugins/neuroCore/php/autoload.php`, файлы ядра не правились.
- [ ] Ядро проверяется на готовность: установлено, включено, есть подключения.
- [ ] Плагин включается и работает без ядра: показывает понятное объяснение, а не падает.
- [ ] Промпт регистрируется при активации **и** при обновлении плагина.
- [ ] Код промпта стабилен и читается в отчёте о расходе (`плагин.что-делает`).
- [ ] `error` в ответе проверяется всегда; при ошибке пользователь видит причину.
- [ ] Адаптеры провайдеров не вызываются напрямую — только через `Neuro\Neuro`.
- [ ] Массовые операции идут через `Queue::push()`, а не циклом в запросе страницы.
- [ ] У заданий заполнены `ref`/`refid`; различающиеся данные — в `payload.tags`.
- [ ] Результаты переносятся в свою таблицу по `task_id` (идемпотентно).
- [ ] Свои эндпоинты закрыты правами, мутации — CSRF-токеном.
- [ ] В журнал и уведомления не попадают ключи, персональные данные и тексты промптов.
- [ ] Проверено на PHP 7.2 (не используются конструкции 7.4+/8.0+).

## Частые ошибки {#chastye-oshibki}

| Что видно | Причина | Что делать |
|---|---|---|
| `prompt_missing` | промпт не зарегистрирован или выключен | регистрировать при активации; проверить в Нейроядре |
| `prompt_tags` | в `tags` нет переменной из промпта | дополнить `tags`; проверять заранее через `Prompt::missing()` |
| `provider_missing` | нет включённых подключений | сообщить администратору, не показывать «ошибка плагина» |
| `provider_key` | ключ не задан или не расшифровывается | администратору: проверить ключ в Нейроядре |
| Задание поставлено, но висит в `new` | не работает планировщик | проверить плагин «Планировщик заданий» |
| Второе задание не создаётся | совпал отпечаток: `code`, версия, `payload`, `iduser` | различать задания данными в `payload` |
| Результат задания пропал | истёк срок хранения (30 дней по умолчанию) | переносить результат в свою таблицу сразу |
| В отчёте о расходе нет вызова | вызван адаптер напрямую или ответ взят из кэша | вызывать только через фасад; `cached` — не расход |
| Ответ не тот, что ожидали | промпт правил администратор (`differs`) | показать расхождение в своём интерфейсе, не перезаписывать |
| `parse`, `schema_errors` | модель ответила не по схеме | упростить схему, описать формат в тексте промпта |
| Медленный ответ на кнопку | в запросе страницы выполняется пачка вызовов | перевести на очередь |

## Совместимость и версии

* Ядро поддерживает PHP 7.2…8.1 — держите свой плагин в тех же рамках.
* Не копируйте классы ядра к себе: обновление ядра исправит ошибку только у того,
  кто пользуется им, а копия останется со старой.
* Проверяйте наличие класса перед использованием (`class_exists('Neuro\\Neuro')`) —
  так плагин переживёт установку рядом с ядром более старой версии.
* `Neuro\Prompt::register()` и `Neuro\Neuro::ask()` — стабильный интерфейс: их
  подпись меняться не будет. Внутренности (`Provider\*`, `Schema`) могут меняться
  между версиями; не опирайтесь на них.
